# 新旧用量入口一致性

日期：2026-09-12；T08 / S03 / S17 的局部验收。原生观察使用 2fa03d89 release EXE；所有数据来自自建隔离 SQLite，非员工数据、非 UAT，也未通过模拟 IPC 返回。

## 固定数据与独立校验

关闭测试客户端后，在本任务临时主目录的空 proxy_request_logs 中写入 4 条合成模型请求。两条 Codex 成功请求、两条 Claude 请求（其中一条 500），共 600 输入 / 60 输出 Tokens，估算费用合计 $0.60。启动真实 EXE 后，原生 get_usage_summary 返回 4 请求 / 660 Tokens / 0.600000，Codex 筛选返回 2 请求 / 330 Tokens / 0.300000。enableLocalProxy=false。

## 界面比对

通过实际导航依次打开独立“使用记录”和旧“设置 → 使用统计”，各检查全部工具和 Codex 两种筛选。逐项比较页面的 Tokens、请求数、费用和每一条可见明细文本，结果完全一致：

| 范围 | 新入口 | 旧入口 | 结果 |
| --- | --- | --- | --- |
| 全部工具 | 660 Tokens / 4 请求 / $0.6000 / 4 行 | 同左 | 一致 |
| Codex | 330 Tokens / 2 请求 / $0.3000 / 2 行 | 同左 | 一致 |

在旧入口通过下拉框选择 5s 自动刷新，真实 get_settings 返回 5000。返回独立入口后下拉框仍为 5s，4 条历史继续显示。截图 `native-usage-entry-parity.png` 为此时的合成数据。完整比较值见 `usage-entry-parity-2fa03d89.json`。

无组织连接时，本人工具事件区域单独显示连接提示，模型历史仍可读取；没有将 Hook 事件伪造成模型请求，也没有为本次测试启用代理或采集。测试结束正常退出，合成数据库保留在本任务临时目录。

## 统计口径说明修正

发现共享 UsageDashboard 的副标题仅描述“使用情况和成本”，未清楚指出本机来源。四种现有语言的 usage.subtitle 已改为：当前设备模型请求与费用估算、不包含 Hook 事件、组织网关账单以管理员后台为准。两个入口共用该组件，因此共同获得说明。

实际 diff 仅四个既有翻译值，JSON 的其他键和值全部一致，无查询、计算、权限或行为修改。按仓库纯文字修改规则不做符号影响分析，也不把已损坏 GitNexus 的空图结果用作安全证明。

验证：四份 JSON 可解析、结构不变，Prettier、typecheck、renderer build 通过；现有 UsageDashboard / RequestLogTable 共 6 项测试通过。没有为文案增加只重复文本的测试。构建保留既有大分块告警。
