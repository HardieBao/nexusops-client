## 1. 首次启动和原有功能

1. 安装并启动客户端。确认固定可见「工作台、工具接入、资产库、使用记录」，以及「组织与上报、设置」。
2. 没有组织时，应显示连接引导，不显示示例组织、虚构费用或成功率。
3. 从工具接入打开个人供应商，从资产库打开个人 Skills、提示词和智能体，从高级工具打开原有 MCP / 会话 / 统一供应商入口。
4. 重启后应恢复上次合法页面。隐藏某个工具后，其专属页应回到有效入口；不应在 Claude 上继续显示 Hermes 记忆或 OpenClaw 专属配置。
5. 验证标题栏最小化、最大化、还原、拖动与关闭；开启“关闭时最小化到托盘”时，关闭后从托盘恢复，内容应保留。另测正常退出和再次启动。

记录：页面、操作、预期与实际结果；有问题时附客户端版本和脱敏截图。

## 2. 连接本人组织

1. 打开「组织与上报」，输入 UAT 地址和测试成员 Key，或选择管理员导出的本人 Team Profile。
2. 读取 Profile 后仍需点击「验证并连接」。确认显示的组织与成员身份正确。
3. 连接本身不应切换当前个人供应商、安装资产或自动开启采集。
4. 用不匹配身份的 Profile 做反例：应拒绝，不得进入他人的上下文。

密钥、Cookie 和登录态不放入截图、验收文档或 Git。需要协助联调时提供已授权会话或本机凭据文件路径，记录中仅保留身份类别。

## 3. 工具配置：先预览，再明确启用

对 Codex 和 Claude Code 分别执行：

1. 先保留一份已有个人配置，记录当前供应商以及相关配置文件的哈希。
2. 进入团队供应商，预览待导入内容。先取消一次：当前供应商与文件哈希应不变。
3. 再次预览并导入。未点击启用前，个人当前配置仍不应切换。
4. 明确启用所选配置并执行连接检测。记录检测结果和时间；失败应有原因，未检测不得显示为实时在线。

“配置已保存”“连接检测通过”“Hook 已注册”“观察到实际事件”是不同状态，分别验收。

## 4. TeamAI Skill / Rule 发布与安装

管理员与成员按各自角色操作，Skill / Rule 各执行一遍：

1. 在客户端资产库使用「选择 Skill 目录」或「选择 Rule 文件」生成候选文件。
2. 管理员在 UAT 资产管理中导入候选，核对类型、内容、上游来源与文件清单，创建 revision。
3. 先发布 Canary，再完成审批，最后发布同一作用域、同一已审批 revision 的 Stable。普通成员不能自行批准发布。
4. 成员在客户端刷新团队资产。审批前不得获得未批准内容；Stable 后应看到授权版本。
5. 预览同步计划，确认目标工具与文件，再明确同步。对两个首发工具核对实际文件集合、revision 和哈希。
6. 修改测试资产的本地内容后再次同步，应先显示冲突；取消应保持文件不变，明确覆盖应保留备份，恢复后哈希应匹配。
7. 撤回或撤销权限后刷新：不能再下载，但界面应如实表示本机已有文件状态，不谎称文件已自动删除。

可复用的合成候选在 evidence/native-skill-candidate-20260912.json 与 evidence/native-rule-candidate-20260912.json，仅用于测试。若重复导入同名样例，记录重复结果，不覆盖他人的业务资产。

## 5. 真实工具事件与管理员查询

1. 成员在组织与上报页阅读字段说明，明确点击「启用采集并上传」。
2. 重启工具并在工具的 Hook 管理入口确认配置。保留其他 Hook；重复启用不应产生多份本功能注册。
3. 分别使用真实 Codex / Claude Code 完成一次受控测试交互，至少触发工具调用。记录时间区间、工具版本和事件类型。
4. 客户端应从“已注册、尚未观察”转为“观察到实际事件”，并显示本人本机历史与待上传状态。
5. 点击「立即上传」或等待正常上传周期，确认待上传得到确认。本机历史不应因队列清空而减少。
6. 管理员按成员、工具、时间筛选，核对新增事件属于同一测试成员。普通成员不能读取管理员统计。
7. 分开检查 Hook 事件、本机模型请求与组织网关费用，不把三者相加。管理员统计不得出现提示词、代码、文件路径或原始会话内容。

task.md 中“20 个唯一事件、5 次重传”的固定数据对账须另留可复核结果；一次人工交互不能替代该场景。

## 6. 断网、关闭采集与切换身份

1. 断开测试网络后产生受控事件，恢复网络再上传；原事件 ID 保持，服务端不得重复入账。
2. 点击「关闭采集并清空待上传」，再触发工具事件：队列与本机聚合不得新增。已有历史按保留规则处理。
3. 测试成员 A 退出，成员 B 登录，B 不得看到 A 的聚合；再次接入 A 时不得静默重新开启采集。
4. 资产安装成功但 ACK 失败时重试，确认只补确认，不重复下载或覆盖文件。

## 7. 回退与问题反馈

UAT 应用回退由部署人员按现有部署锁、镜像 digest 和备份记录执行。已记录的 23a56574 / 9a3022a0 回退只证明对应场景，不自动覆盖本次用户完整联调。参见 [UAT 部署与回退证据](evidence/uat-deployed-20260911.md)。
